**SHOULD FIX 1: the S-6.md §5 hunk `@@ -38,3 +38,3 @@` has no leading context.**
- **Under `git apply`:** a hunk must be anchored to the start of the file only when its old start line is 0 or 1. It must be anchored to the end only when it has no trailing context. Neither applies here (start line 38, two trailing lines), so git tries the exact position first. The S-6.md offset is still 0 at that point, so line 38 matches and the hunk should apply without `--unidiff-zero`. I am reasoning from git's source here, not from running it.
- **Elsewhere it is fragile:** `git diff` never produces uneven context in the middle of a file, so this hunk was clearly edited by hand. GNU `patch` may treat a hunk with less leading than trailing context as anchored to the start of the file and then reject it or apply it with fuzz. If the file drifts, there is no leading context to locate it.
